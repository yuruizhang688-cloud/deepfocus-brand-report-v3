## 品牌介绍

### 让好的品牌在 AI 时代，不止于被看见和推荐。

用户会向 AI 描述需求、追问差异，也会要求给出选择理由。品牌需要关注的不只是名字有没有出现，还包括信息是否准确、优势是否讲清，以及答案有没有可靠来源。

DeepFocus 从真实用户意图出发，整理品牌事实，建设内容与信源，再通过约定的问题集持续复测。交付围绕品牌的业务目标展开，并保留内容执行与效果复测的记录。

| 原则 | 执行要求 | 对应记录 |

### 提示词从真实问题与产品优势场景出发

问题来源包括售前、售中、售后的真实对话；抖音、小红书、知乎等平台的用户讨论；品牌产品线、核心卖点与重点市场；以及比较型、评测型、选型型问题。

整理问题时，保留用户的选型条件，确认哪些场景能由品牌事实支撑。提示词清单需要能解释“用户为什么会这样问”，也要能追溯到原始表达或品牌场景。

问题感知 → 问题界定 → 方案理解 → 专业验证 → 行动转化

问题感知与问题界定更多对应塔基问题；方案理解更多对应塔身；专业验证与行动转化更容易出现塔尖问题。这是问题组织方式，具体布局需结合证据，不预设固定百分比分配。

### 品牌知识库统一对外事实

知识库作为唯一对外口径，重点是真实性与时效性。先归集品牌、产品和 FAQ，再拆为独立知识点，标明适用范围与版本；每项事实关联原始出处、确认状态及引用它的内容。资料变化后同步更新并保留修改记录。

归集事实 → 结构化拆解 → 关联证据 → 持续维护

### 监测结果用于发现缺口与安排复测

自动化采集保留问题、平台和原始回答；可视化看板集中呈现品牌提及、引用来源和变化趋势；策略分析据此识别内容缺口，提出优化建议，并跟进复测。

监测关注品牌可见度、认知准确性、负面舆情和竞品动向。实际平台、入口、采样频率与覆盖范围在项目开始时约定，对外结果按网页端口径呈现。

### 内容从用户意图出发，审核后发布

意图拆解 → 事实调用 → 结构规划 → 内容生成 → 人工审核

内容围绕同一主题组织标题、导语与正文，用结论速览、场景选择、对比表、分级标题和 FAQ 回应用户的了解、比较与决策需求。每项表述回到知识库核对，审核后进入发布流程。

## 交付与评估

### 五阶段交付体系

系统的诊断 → 针对性的策略 → 专属的内容体系 → 共建 KPI 验证体系 → 持续优化与迭代

每个阶段由「执行动作」与「核心交付」共同定义。

#### 阶段 1 · 系统的诊断

| 执行动作  | 内容                       |
| ----- | ------------------------ |
| 全平台扫描 | 在目标市场的主流 AI 平台上全面扫描可见度表现 |
| 深度分析  | 分析品牌出现频率、推荐排名、评价倾向       |
| 竞品对标  | 与主要竞品进行多维度的可见度对标         |
| 风险识别  | 识别品牌 AI 认知优势点与潜在风险       |

**核心交付**：可见度基线数据 ／ AI 认知画像 ／ 竞品分析与风险识别

#### 阶段 2 · 针对性的策略

| 执行动作  | 内容                              |
| ----- | ------------------------------- |
| 专属策略  | 基于诊断数据和行业经验，为品牌制定专属的 GEO 优化策略   |
| 场景矩阵  | 构建用户提问场景矩阵，系统梳理用户可能向 AI 提出的关联问题 |
| 优先级排序 | 确定哪些平台、场景、关键词最需要优先突破            |
| 阶段执行  | 分阶段实施——短期速赢 + 中期深耕 + 长期壁垒       |

**核心交付**：整体思路与逻辑框架 ／ 平台 × 场景 × 关键词矩阵 ／ 分阶段实施计划 ／ 预期效果目标（量化的阶段性 KPI）

#### 阶段 3 · 专属的内容体系

| 执行动作    | 内容                              |
| ------- | ------------------------------- |
| 专属知识库   | 建立品牌专属知识库，系统化梳理品牌核心信息资产         |
| 原生内容生成  | 基于策略生产高质量的 GEO 原生内容，契合各 AI 平台偏好 |
| 全网矩阵式铺设 | 制定多渠道内容分发计划，最大化影响 AI 知识体系       |
| 多维质检    | 通过 30+ 维度的分析体系，严格把控内容质量与合规性     |

**核心交付**：品牌专属知识库 ／ GEO 优化原生内容（针对各主流 AI 平台定制）／ 分发计划与执行 ／ 质量分析验证报告

#### 阶段 4 · 共建 KPI 验证体系

| 执行动作     | 内容                            |
| -------- | ----------------------------- |
| 共识目标     | 与客户共建品牌 AI 可见度 KPI 体系，确保目标共识  |
| 量化对比     | 定期生成数据报告，量化对比优化前后的各维度变化       |
| **独立验证** | **通过多设备、多网络环境的独立验证，确保数据真实可信** |
| 全量存储     | 提供可视化数据看板，数据全量存储，支持历史回溯       |

**核心交付**：KPI 达成情况（排名、认知比例、竞品差距等）／ 可见度变化趋势（多维度折线图与对比图）／ 竞品动态分析 ／ 下阶段优化建议

> **为什么"独立验证"值得单独强调？**  
> AI 答案具有概率性——同一个问题在不同设备、不同网络、不同时间可能得到不同回答。只用一台电脑、一次截图得出的结论，不构成证据。  
> 我们通过多设备、多网络环境的独立验证，让每一条数据都能被复现。**这是我们与"截图式交付"最本质的区别。**

#### 阶段 5 · 持续优化与迭代

| 执行动作  | 内容                        |
| ----- | ------------------------- |
| 全天候监控 | 监测系统全天候运行，动态追踪表现变化        |
| 动态优化  | 基于最新数据持续优化策略与内容，拒绝一次性交付   |
| 竞品追踪  | 竞品动态实时追踪，竞品发生异常变化时及时调整    |
| 算法适配  | AI 平台算法更新和模型迭代后快速适配，保持竞争力 |
| 异常响应  | 负面舆情或排名异常的应急处理            |

**核心交付**：持续优化建议与执行 ／ 月度复盘报告 ／ 行业趋势洞察分享

官网修改、资料授权等事项需品牌方确认或配合。DeepFocus 负责约定范围内的问题研究、内容制作、分发、监测和复盘；项目启动时明确各方负责人。

### 看提及，也看推荐的分母

| 观察项 | 计算或记录方式 | 阅读时需核对 |
| --- | --- | --- |
| 品牌提及率 | 提到品牌的有效回答数 ÷ 全部有效测试数 | 问题集、平台、时间与有效样本 |
| 首位／前三推荐 | 同时展示在“提到品牌的回答”中所占比例，以及在“全部有效测试”中所占比例 | 两种分母分别列示，避免混读 |
| 事实准确性 | 核对可验证的品牌信息，统计其中准确的比例 | 无法核实的单列，不能当作正确 |
| 引用来源 | 保留 AI 回答引用的具体来源 | 来源能否回查、是否与品牌事实一致 |
| 竞品差距与情感 | 分别记录竞品表现及正面、负面、中性描述 | 同条件比较，保留分类依据 |

### 答案变化、网站访问、客户询盘分开说明

前后尽量使用同样的问题和测试条件，不同市场、场景分别确认起点与观察期。回答变化可以说明 AI 中的品牌呈现，网站访问和询盘需要各自的数据支持；几项指标同时增长不能直接证明因果关系。

AI 回答存在波动。项目通过约定样本、原始回答和周期复测判断变化，不承诺每次回答都排第一，也不设统一的见效天数。
